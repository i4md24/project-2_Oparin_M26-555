# Primitive DB (primitive_db)

Консольный эмулятор реляционной базы данных: управление таблицами,
CRUD-операции, валидация типов, декораторы (обработка ошибок, подтверждение
опасных операций, замер времени) и кэширование результатов select на замыкании.

## Установка

Требуется uv версии 0.5+:

- uv sync — установка пакета и зависимостей в .venv;
- либо из собранного дистрибутива: uv build, затем uv tool install dist/*.whl.

## Управление таблицами

Запустите команду database (или project) — откроется интерактивный режим
работы с таблицами. Метаданные таблиц хранятся в файле db_meta.json
в текущей директории.

### Создание таблицы

    create_table <имя_таблицы> <столбец:тип> ...

Типы столбцов: int, str, bool. Первичный ключ ID:int добавляется
автоматически.

    Введите команду: create_table users name:str age:int is_active:bool
    Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

### Список таблиц

    Введите команду: list_tables
    - users

### Удаление таблицы

    Введите команду: drop_table users
    Таблица "users" успешно удалена.

При попытке удалить несуществующую таблицу:

    Ошибка: Таблица "products" не существует.

## Работа с данными

Данные таблиц хранятся в файлах data/<имя_таблицы>.json в текущей директории.
Первичный ключ ID:int генерируется автоматически: максимум существующих
значений плюс один. Условие where сравнивает значение столбца с указанным,
приводя его к типу столбца.

### Добавление строки

    insert into <имя_таблицы> values (<значение>, ...)

Значения перечисляются через запятую в порядке столбцов, столбец ID
указывать не нужно. Кавычки не используются: 25, true, Anna.

    Введите команду: insert into users values (Anna, 25, true)
    Строка с ID = 1 успешно добавлена в таблицу "users".

При неверном значении или числе значений:

    Ошибка: значение "двадцать" для столбца "age" не приводится к типу int.
    Ошибка: неверное число значений для таблицы "users": ожидалось 3, получено 1.

### Просмотр строк

    select from <имя_таблицы> [where <столбец> = <значение>]

Без условия выводятся все строки таблицы, с условием — только подходящие:

    Введите команду: select from users
    +----+-------+-----+-----------+
    | ID |  name | age | is_active |
    +----+-------+-----+-----------+
    | 1  |  Anna |  25 |    True   |
    | 2  | Boris |  30 |   False   |
    +----+-------+-----+-----------+

    Введите команду: select from users where is_active = false
    +----+-------+-----+-----------+
    | ID |  name | age | is_active |
    +----+-------+-----+-----------+
    | 2  | Boris |  30 |   False   |
    +----+-------+-----+-----------+

### Изменение строк

    update <таблица> set <столбец> = <значение> where <столбец> = <значение>

Изменяются все строки, подходящие под условие; в отчёт выводится их число:

    Введите команду: update users set age = 26 where name = "Anna"
    Обновлено строк: 1.

Если ни одна строка не подошла:

    Подходящих строк не найдено.

Столбец ID изменять нельзя:

    Ошибка: Столбец "ID" изменять нельзя, он генерируется сам.

### Удаление строк

    delete from <имя_таблицы> where <столбец> = <значение>

    Введите команду: delete from users where ID = 2
    Удалено строк: 1.

При работе с несуществующей таблицей:

    Ошибка: Таблица "products" не существует.

## Декораторы и замыкания

Все операции ядра обернуты в декораторы из модуля primitive_db.decorators:
декораторы добавляют общее поведение (перехват ошибок, подтверждение,
замер времени), не меняя код самих операций.

### Обработка ошибок

Декоратор handle_db_errors перехватывает исключения операции и печатает
понятное сообщение вместо traceback, после чего программа продолжает
работать. Если файл db_meta.json поврежден:

    Ошибка валидации: Expecting value: line 1 column 1 (char 0).

Если файл данных таблицы отсутствует:

    Ошибка: Файл данных не найден. Возможно, база данных не инициализирована.

### Подтверждение опасных операций

confirm_action — фабрика декораторов: вызов confirm_action("удалить строки")
возвращает сам декоратор, а текст вопроса хранится в замыкании. Перед
delete и drop_table программа спрашивает подтверждение:

    Введите команду: delete from users where ID = 1
    Вы уверены, что хотите удалить строки? (да/нет): нет
    Действие отменено.

Порядок декораторов важен: у delete таймер log_time обернут ближе
к функции, чем подтверждение, поэтому при ответе «нет» строка о времени
не печатается.

### Замер времени

Декоратор log_time замеряет время работы через time.monotonic() и печатает
отчет после каждой операции insert, select, update и delete:

    Функция select выполнена за 0.000139 с.

Имя функции берется из func.__name__, которое сохраняет functools.wraps:
без него все три декоратора печатали бы "wrapper".

### Кэширование select

Функция create_cacher из модуля primitive_db.caching строит замыкание
и возвращает вложенную функцию cache_result(key, value_func): словарь
с результатами живет в замыкании, снаружи недоступен, но сохраняется между
вызовами. Повторный select с тем же запросом получает готовую таблицу
из кэша, не пересчитывая ее.

Ключ кэша — пара (таблица, условие where): select from users и
select from users where is_active = false хранятся по отдельности.
Ошибочный запрос (select вернул None) в кэш не попадает, поэтому сообщение
об ошибке печатается при каждом повторе.

После любой команды, меняющей данные (create_table, drop_table, insert,
update, delete), движок пересоздает кэшер: новый вызов create_cacher
дает новый пустой словарь. Без этой пересборки select показывал бы
устаревшие строки.
